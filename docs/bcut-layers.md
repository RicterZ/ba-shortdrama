## 必剪视觉分层

`render_bcut_layers.py` 直接调用制作视频所用的 Remotion 模板，把背景、角色、界面、字幕以及片头分别渲染为透明 PNG，再将动态片段编码为保留 alpha 的 MOV。动态部分逐帧渲染、不抽帧；已证明恒定的背景、固定按钮栏，以及进场结束且没有动作、移动、转身、气泡的 official 角色状态复用同一渲染帧。复用状态按说话人、压暗、表情、光照等实际输入区分。组件未挂载的时段直接留空。连续且内容相同的帧合并为一个素材片段。画布大小、帧率和时间都来自 `scene.json`。

支持 `official` 和 `who-is-the-spy`。打字、闪烁箭头、人物进场、动作、走位、转身、气泡、暗角、聚光灯、双描边等使用原模板代码。角色轨道按舞台叠放次序排列；同一轨在不同镜头可能对应不同角色，谁是卧底的聚光人物也会换到最上层。

透明图层分别做叠化无法还原整幅画面的叠化。因此仅在转场重叠期间使用完整画面的短片段，并在该区间清空普通分层。转场之外仍为分层素材。谁是卧底片头因原模板的 CSS 层级与角色、词牌交错，也采用短的完整合成片段。对转场中某个角色的单独调整需要重新导出对应转场。

静态 PNG 和动态透明 MOV 片段能在必剪中移动、缩放、替换和调整时间，但图内的文字与效果不是必剪原生文本或原生关键帧。默认字幕图层包含原模板文字，保留字形、双描边与打字效果。`official` 的 `dialogue` 图层只包括对白底部渐暗、姓名、社团、分割线和箭头，留出正文给原生字幕；原生字幕的字体布局和出字效果需要独立验证，不能把两种模式说成等价。

导出器的 `--captions editable` 对应 `render_layers(..., editable_captions=True)`，支持两种模板。此时普通图层和转场片段都不绘制待编辑文字，避免与原生字幕重复；原生正文没有逐字出现或转场淡入淡出。谁是卧底的词牌、投票字、心理字幕与发言由导出器生成原生文本，字形和描边与原模板可能不同。

界面按实际 CSS 层级分为选项、按钮和固定按钮栏；谁是卧底另外分开词牌、投票字、心理字幕与大字幕，避免对白底部渐暗遮住按钮，或投票字错误覆盖控件。默认轨道排列与模板的叠放次序一致。

完整导出会比静态工程慢。中间 PNG 帧在打包时合并为透明 MOV，避免必剪导入几千张图片时耗尽文件句柄；静态段仍可保留为 PNG。渲染过程打印正在处理的图层及帧进度。图片文件名由内容哈希产生，相同图片复用。

默认并发为 4，可通过 `BCUT_RENDER_CONCURRENCY` 调整。提高并发不一定更快，应按实际机器负载测量。

`effect_audio_events(scene)` 返回按钮、选项、气泡与片头音效的时间、音量和起始裁剪；配音、逐句点击音、系统语音、BGM 由工程导出器另行处理。

开发验证可运行 `uv run python code/ba-production/scripts/check_bcut_layers.py --episode 001-momoi-pilot`。该检查渲染一个短夹具，对比分层重新合成与普通模板渲染，包括转场；允许透明 PNG 在 8 位通道合成时的少量舍入误差。它不能替代在必剪应用里打开工程后的预览与音频验证。
